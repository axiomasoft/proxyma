## Наблюдения во время прогона

- В серии снимков `pg_stat_activity` с интервалом около секунды повторялись ожидания
  `pxm_route_health`, `prc_process_lanes` и `pxm_budgets`. Записи показывают наблюдения,
  а не число уникальных транзакций; блокирующий процесс сам мог ожидать другую транзакцию.
- Разность двух снимков `pg_stat_statements` для одной запущенной БД показала 153 вызова
  блокировки route health с суммарным временем около 20 с, 203 вызова одной из блокировок
  Process lane с 15,3 с и 1160 поштучных budget locks с 7,3 с. Суммы параллельных
  ожиданий нельзя складывать как wall time. Счётчики SQL не измеряют выполнение PHP.
- `HealthRepository::window()` повторно читает наблюдения в окне под health locks.
  Пробный `EXPLAIN ANALYZE` на текущих тестовых данных показал последовательное чтение
  обеих таблиц и около 2,6 мс на запрос с 445 строками. Оценка использовала аналогичный
  фильтр и не является замером полной стоимости обработки окна в PHP. В выборке из 492
  наблюдений полные JSON занимали 713892 байта против 603192 для поля `result`;
  одно сокращение projection само по себе не доказывает достаточное ускорение.

Сырые временные наблюдения находятся в `/tmp/proxyma-plan2-baseline-waits.jsonl`,
`/tmp/proxyma-plan2-blockers.jsonl` и `/tmp/proxyma-plan2-pgstat-{midpoint,next}.jsonl`.
Они диагностические и не заменяют штатные native reports. До изменения owning source
необходимо сопоставить закончившийся полный профиль с этими наблюдениями и проверить
гипотезу на той же нагрузке, сохраняя все блокировки и проверки.

## Проверяемое изменение

В рабочем source бюджетные строки блокируются ограниченными группами, отсортированными
по прежнему ключу `scope_key`, затем `tenant_key` с collation `C`. Сохраняются `FOR UPDATE`,
проверка наличия и identity каждой строки и существующий порядок относительно других tiers.
Гипотеза: меньше SQL round trips внутри транзакций сократит удержание ранних locks;
одни только выполненные тесты этого не доказывают.

Изолированные package проверки: `MultiScopeReservationTest` — 21 тест / 134 assertions;
`GcraReservationTest` — 5 тестов / 60 assertions, с раздельными процессами. Первый тест
проверяет также границу группы и исключение конкурирующей транзакции. Целевой PHPStan
прошёл. Реальное ускорение и полная квалификация ещё не проверены.
